## Architecture Overview
Understanding the add-on lifecycle is crucial for building robust extensions. Each add-on follows a three-phase initialization sequence:
<Steps>
1. **Discovery** - The API scans registered add-ons
2. **Instantiation** - Add-on constructors execute
3. **Initialization** - The `init()` method receives the API instance
</Steps>

## Implementation Blueprint
### Base Add-on Structure
The next example assumes that you are in `MyBasicAddon/index.js` file.
```js
/** @import { API } from "easy-api.ts" */
const { Addon } = require("easy-api.ts")

class MyBasicAddon extends Addon {
    name = "@eats/example"
    description = "My awesome addon description."
    version = "1.0.0"

    /**
     * Starts the addon initialization protocol.
     * @param {API} api The API instance.
     */
    init(api) {
        // Addon initialization implementation...

        // TIP:
        // You can load custom functions through the addon using
        // api.functions.load(dir: string)
    }
}

module.exports = MyBasicAddon
```
### Register The Add-on
You need to import the addon in your main file and define an `Addon` array inside API constructor.
The next example assumes that you are in `index.js` file.
```js
const MyBasicAddon = require("./MyBasicAddon")
const { API } = require("easy-api.ts")

const api = new API({
    addons: [
        new MyBasicAddon(),
    ],
    // ...
})
```
